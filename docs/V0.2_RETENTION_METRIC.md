# V0.2「7 日同人格有效复用率」服务端口径

状态：本地代码已实现并完成自动化验证；尚未部署，也尚无真实用户数据。该指标用于验证产品假设，不代表留存假设已经成立。

## 计算定义

按 UTC 自然日形成基准日 cohort：

- 分母：匿名设备先确认人格，随后第一次从服务端获得该人格的成功 AI 回复。该成功回复所在 UTC 日期为基准日。
- 分子：从基准日后的第 1 至第 7 个 UTC 自然日内，任意一个自然日中，同一匿名设备使用基准人格获得至少两次成功 AI 回复。
- 同一基准日内的更多回复不进入分子；分散在两个不同后续日期的各一次回复也不合并。
- 同一设备在本轮基准窗口内最多进入一次分母、一次分子。
- `rate = numerator / denominator`；分母为 0 时返回 0。

“成功 AI 回复”只由 `src/server/chat.ts` 判定：模型上游 HTTP 成功，且响应中存在非空回复后才记录。参数校验失败、额度拒绝、模型未配置、上游错误、超时或空回复均不记录。

## 匿名关联与隐私边界

- 客户端通过 `x-zodiac-device` 发送本地随机设备标识；聊天请求仅在当前人格已本地确认时，额外发送安全的 `x-zodiac-confirmed-persona` 人格 ID，避免异步确认遥测晚到造成首答漏记。
- 服务端使用稳定的 `RATE_LIMIT_SALT` 与设备标识做 SHA-256；留存哈希不包含 IP，也不返回前端。
- KV 键和值不保存原始设备标识、IP、聊天正文或问卷答案。
- 单设备最小状态只包含人格 ID、UTC 日期、当日成功次数和是否已达标；状态 TTL 为 10 天。
- cohort 聚合只包含分母和分子；每次更新后的 TTL 为 35 天。

匿名哈希仍属于受限运营数据，KV 访问权限应限制在服务端运维范围内；不要导出为用户名单。

## 配置与降级

可信统计同时要求：

1. 配置非空、稳定且不公开的 `RATE_LIMIT_SALT`；轮换该盐会切断跨日匿名关联。
2. 绑定持久化 `ZODIAC_KV`。
3. 浏览器请求携带 `x-zodiac-device`。

`persona_confirmed` 缺少盐或 KV 时返回 `503 RETENTION_NOT_CONFIGURED`，缺少设备标识时返回 `400 MISSING_DEVICE_ID`。前端确认人格仍保存在本地，不依赖该遥测响应。聊天成功路径遇到上述配置缺失或 KV 写入异常时安全降级为“不写留存”，不会把一次有效聊天改成失败。

若 `persona_confirmed` 异步请求晚于首个聊天成功到达，服务端只在 `x-zodiac-confirmed-persona` 与本次聊天人格完全一致时补建确认状态；晚到的确认事件不会重复增加分母。

## 服务端读取

当前不增加公开 API、看板或管理 UI。服务端代码可调用：

```ts
const metric = await readRetentionMetric("2026-08-01", env);
// { denominator, numerator, rate }
```

实现位于 `src/server/retention.ts`，输入只接受有效的 `YYYY-MM-DD` UTC 日期。

## 当前限制

- 尚无真实流量，因此市场与留存结论仍是假设。
- 当前 `KeyValueStore` 只提供 `get/put`，cohort 聚合采用读后写；适合 V0.2 小流量验证，但并发写入不具备原子计数保证。正式放量前应切换到平台原子计数器、事务存储或单写者聚合。
- 本轮没有新增查询端点，读取需在可信服务端环境中进行。
