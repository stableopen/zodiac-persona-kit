# AI星座搭子 V0.2 产品决策简报

状态：范围冻结，本地交付与所有者验收通过，待部署
日期：2026-08-01

## 决策来源

本简报由三份彼此独立的输入裁决形成：

- 产品经理：优先证明“用户愿意在另一个自然日继续使用同一人格”。
- 市场增长：优先建立“结果可邀请朋友参与”的传播闭环，并将商业结论保留为待验证假设。
- UI/UX：优先让用户在短时间内真实感知两种人格表达的差异，而不是继续展示抽象参数。

CEO 裁决：V0.2 以“同题双声道”为唯一核心体验；“确认为我的搭子”是留存承接，“把同一选择发给朋友”是传播承接。关系匹配、付费、长期记忆等不进入本期。

## 目标用户与核心问题

目标用户：第一次接触产品、对星座或 AI 人格感兴趣，但尚不相信“换一种 AI 沟通方式”有实际差异的普通中文用户。

核心问题：V0.1 能给出漂亮的人格结果，但用户仍难以立刻感知该人格和其他人格究竟哪里不同，也缺少一个朋友收到后能马上参与的分享内容。

## 一句话价值

> 同一道题，让两种 AI 回答给你听；选出更对味的那个，再让朋友也选一次。

## 唯一核心体验闭环

```text
6题测试或直接选择
→ 看到两种人格对同一通用情境的短回答
→ 点击“这句更对味”
→ 揭示差异原因并主动确认为“我的搭子”
→ 可继续聊天或分享同一场 A/B 选择
→ 朋友打开后无需注册即可选择，再进入自己的测试
```

双声道使用人工审核的通用情境和预置回复，不调用额外模型，不使用用户聊天正文。

## 本期做什么

1. 同题双声道
   - 用少量通用情境展示两个人格的表达差异。
   - 用户选择前不突出星座名称，减少身份偏见。
   - 选择后用一句普通话解释差异，而不是只展示六轴数字。
2. 用户主动确认
   - 选择后提供“设为我的 AI 搭子”。
   - 只在浏览器本地保存确认的人格和最近会话；不建立账户或云端历史。
   - 再次打开首页时提供“继续和某某搭子聊”。
3. 互动分享深链
   - 分享 URL 只包含情境、两个人格、分享方选择和匿名来源标识。
   - 接收者先参与同一场 A/B 选择，再被引导完成自己的测试。
   - 不在 URL、卡片或事件中放入用户问题、答案或聊天正文。
4. 必要体验修复
   - 测试支持上一题、选择反馈、换题后回到题目标题。
   - 手机聊天始终可返回结果。
   - 首次成功回复前不突出额度；失败态支持重试。
   - 移除无效 GitHub 外链，保留 V0.1 的测试、直接选、结果、聊天、分享、Prompt/JSON 和 `/explore`。
5. 事件区分
   - 区分双声道展示、选择、搭子确认、分享生成、分享链接打开和受邀选择。
   - 事件只记录允许的事件名、人格 ID、通用情境 ID、日期桶和匿名来源；不记录正文。

## 本期不做什么

- 不做星座配对、情侣匹配、双人关系报告或“拿捏/折磨”等确定性判断。
- 不做每日运势、星盘、更多人格或长篇测试报告。
- 不做登录、云端聊天、好友系统、社区、排行榜或长期记忆。
- 不接支付、广告、会员、人格市场或商业意向表单。
- 不增加双模型实时回答；双声道先使用审核过的预置内容。
- 不引入 CrewAI、MetaGPT、elizaOS、SillyTavern 等重型运行时或受限许可证代码。
- 不重做整站视觉，也不同时制作多种社媒尺寸。

## 产品验收标准

1. 新用户能在移动端完成“测试/选择 → 双声道 → 选择 → 确认搭子”，且无需登录、无需模型请求。
2. 双声道两条回复均为短文本，用户能在约 15 秒内完成选择；这是最小可逆的产品设计参数，不是用户数据结论。
3. 选择后明确解释两种沟通方式差异，并能进入现有真实聊天路径。
4. 刷新或再次打开首页时，能看到已确认人格和“继续聊天”；信息仅保存在当前浏览器。
5. 分享深链能恢复同一情境和两种回答，接收者无需注册即可选择。
6. 分享链接、海报和匿名事件均不含问卷答案、用户问题或聊天正文。
7. 390×844 手机尺寸下，主路径无横向滚动；测试可返回上一题；聊天页始终有返回结果入口和可用输入区。
8. V0.1 的直接选择、12 人格浏览、聊天、分享、Prompt 复制与 JSON 下载继续可用。
9. 人格数据校验、推荐算法、API 安全测试、类型检查和生产构建继续通过。

## 唯一北极星指标

**7 日同人格有效复用率**：首次获得成功 AI 回复并确认人格的匿名设备中，在之后另一个自然日使用同一人格再次获得至少两次成功回复的比例。

V0.2 同时观察两个诊断指标：双声道选择完成率、受邀者选择完成率。它们用于解释传播摩擦，不替代北极星指标。

## 市场与商业假设

以下均未经真实用户数据验证：

1. 假设：A/B 语言选择比单纯星座结果更容易让朋友参与。
   - 验证：比较 `duel_view → duel_choice → share_generated → referral_open → referred_choice`。
2. 假设：用户主动确认人格后，比算法自动给结果更愿意跨日复用。
   - 验证：按匿名设备与日期桶计算同人格有效复用，不记录正文。
3. 假设：第一笔收入更可能来自品牌/活动白标定制，而不是 C 端 Prompt 售卖。
   - 验证方式（不在 V0.2 实现）：用现有模板制作一个品牌样例，定向接触少量真实客户，观察沟通和报价请求。

在获得真实复用与传播数据前，不宣称商业模式成立，不启动付费开发。

## 开源借鉴边界

- 可借鉴 SillyTavern 的角色卡、elizaOS 的人格/动作/记忆分层、prompts.chat 的公开内容增长、CrewAI/MetaGPT 的角色化协作方法。
- 仅借鉴机制；不复制 AGPL、限制性社区许可证或未经审计的实现。
- 内部人格 JSON 保持稳定并为 Character Card 映射预留空间，但 V0.2 不承诺兼容未完成许可证审计的格式。
